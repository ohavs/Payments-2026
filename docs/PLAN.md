# תוכנית: מאפליקציית ווב לאפליקציית אנדרואיד + עיצוב מחדש

> מסמך עבודה. כל שלב בתוכנית מסתיים במשהו שעובד ואפשר לבדוק אותו בטלפון.
> לפני שמתחילים לכתוב קוד, צריך לסגור את ההחלטות שבסעיף 10.

---

## 0. בקצרה

1. **אנדרואיד עם Capacitor, בלי לכתוב הכול מחדש.** קוד ה־React הקיים נארז בתוך אפליקציה נייטיב אמיתית (APK/AAB). כך מקבלים התראות נייטיב, כניסה עם Google נייטיב, רטט (haptics), כפתור "חזור", מסך פתיחה, ובהמשך גם ווידג'ט למסך הבית. אותו קוד ממשיך לשרת גם את גרסת הווב.
2. **קודם תשתית, אחר כך עיצוב.** היום הקוד עובר קומפילציה בתוך הדפדפן (Babel) ונטען כגרסת פיתוח של React. זה איטי, ולא יעבוד בתוך APK. שלב 1 מעביר את הפרויקט ל־Vite עם build אמיתי.
3. **התראות מקבלות טיפול מלא.** מצאתי באג שבגללו תזכורות מפסיקות להגיע אחרי המחזור הראשון (פירוט בסעיף 1). מתקנים אותו ועוברים להתראות מקומיות שמתוזמנות על המכשיר, ובנוסף FCM נייטיב לאירועים שמגיעים מהשרת.
4. **שפת עיצוב חדשה לפי הרפרנס:** פונט עגול וכבד, מספרים ענקיים, כרטיסים לבנים, רקעי פסטל, אייקונים צבעוניים עם קו מתאר שחור, כפתור + ירוק עם מסגרת שחורה, גרפים בצורת גלולות, ואנימציות קפיציות בכל מקום.
5. **7 שלבים.** אחרי כל אחד יש משהו שאפשר להתקין ולהרגיש.

## 1. מה יש היום בקוד, ומה מפריע לאנדרואיד

| נושא | מצב היום | למה זו בעיה |
|---|---|---|
| Build | 15 קבצי `.jsx` עוברים קומפילציה **בזמן ריצה** עם `@babel/standalone`, ו־React נטען כ־`react.development.js` | פתיחה איטית בטלפון. בתוך APK אין לזה מקום |
| מודולים | כל קובץ חושף פונקציות דרך `Object.assign(window, …)` | אין import/export, אין tree-shaking, קשה לתחזק |
| Firebase | סקריפטי compat נטענים מ־`/__/firebase/…` ו־`/__/firebase/init.js` | הנתיבים האלה קיימים **רק ב־Firebase Hosting**. בתוך ה־APK הם לא יטענו בכלל |
| כניסה | `signInWithPopup` של Google | **לא עובד בתוך WebView**. צריך כניסה נייטיב |
| טוקן התראות | שדה אחד `fcmToken` ב־`settings/main` | מכשיר שני דורס את הראשון, ורק מכשיר אחד מקבל התראות |
| **באג בתזכורות** | `nextDate` נשמר פעם אחת ולא מתקדם לעולם (`isAutoPaid` = התאריך עבר) | אחרי החיוב הראשון התשלום מסומן "שולם" לתמיד. **אין יותר תזכורות** ללוח השנה ולפונקציית הענן, ולוח השנה מציג רק מופע אחד (גם במנוי שבועי) |
| סיכום חודשי | יש מתג `monthlySummary` בהגדרות | אין שום קוד ששולח סיכום |
| ייצוא CSV/PDF | כפתורים קיימים | מציגים "יתווסף בהמשך" |
| ביצועים גרפיים | glassmorphism, `backdrop-filter: blur`, ועיגולי רקע מטושטשים | יקר מאוד ב־WebView של אנדרואיד ופוגע בחלקות האנימציות. גם לא מתאים לשפה החדשה |
| סגנון | כ־5,700 שורות עם inline styles | אין design system, ושינוי עיצובי גורר עריכה בכל קובץ |
| בדיקות | אין | שינוי גדול בלי רשת ביטחון |
| משתמש אנונימי | "המשך ללא חשבון" יוצר uid שקשור לדפדפן | באפליקציה ייווצר uid חדש **והנתונים לא יעברו** (פתרון בסעיף 8) |

את הלוגיקה עצמה שווה לשמור כמו שהיא: חישובי התקציב (`computeBudgetStats`), קטלוג השירותים, ההמרה בין מטבעות, השיתוף באימייל וחוקי Firestore. היא עובדת, וצריך רק להעביר אותה למודולים.

## 2. ההחלטה הטכנולוגית: איך הופכים לאנדרואיד

| אפשרות | יתרונות | חסרונות | מסקנה |
|---|---|---|---|
| **Capacitor 8** (עוטף את קוד ה־React באפליקציה נייטיב) | שומר כ־80% מהקוד. RTL ב־WebView יציב לגמרי. פלאגינים נייטיב רשמיים להתראות, Google Auth, haptics ו־status bar. אותו קוד משרת גם ווב (ובעתיד iOS) | האנימציות רצות ב־WebView, ולכן צריך משמעת: רק `transform`/`opacity`, בלי blur | ✅ **מומלץ** |
| React Native / Expo | ממשק נייטיב "אמיתי" ואנימציות על ה־UI thread | כתיבה מחדש של כל ה־UI. RTL ב־RN בעייתי (`I18nManager.forceRTL` דורש restart ויש בו הרבה מקרי קצה) | ❌ עלות גבוהה, וסיכון RTL |
| TWA (PWA בתוך Chrome) | כמעט בלי עבודה | ההתראות נשארות Web Push. אין התראות מקומיות, אין ווידג'ט, אין כניסה נייטיב | ❌ לא פותר את מה שביקשת |
| Kotlin / Flutter | הכי נייטיב שיש | כתיבה מחדש מאפס | ❌ |

**למה Capacitor מתאים כאן במיוחד:** האפליקציה כתובה כולה בעברית RTL, ו־WebView מטפל ב־RTL באופן מושלם. בנוסף אני יכול להריץ את הממשק בדפדפן מקומי בסביבת הפיתוח, לצלם כל מסך ולוודא שהוא נראה נכון לפני שהוא מגיע לטלפון שלך. ב־React Native זה כמעט בלתי אפשרי.

**איך זה ייבדק:** אין כאן אמולטור אנדרואיד (אין KVM). לכן:
- את הממשק אבדוק ב־Chromium במידות טלפון (393×852, עברית) עם צילומי מסך.
- ה־APK ייבנה ב־GitHub Actions, ואתה תתקין אותו בטלפון.

## 3. ארכיטקטורה חדשה

### Stack
- **Vite 8** כ־build, ו־**React 19**
- **Tailwind CSS 4** עם CSS variables לטוקנים. יש בו utilities לוגיים (`ms-`/`me-`/`ps-`/`pe-`/`start-`/`end-`) שמתאימים ל־RTL בלי טריקים
- **motion 14** (לשעבר Framer Motion) לאנימציות: springs, gestures, layout animations ו־`AnimatePresence`
- **@number-flow/react** למספרים שמתגלגלים ספרה אחר ספרה, כמו מכונת מזל
- **Firebase JS SDK 13** בגרסה המודולרית, עם config מפורש (במקום `/__/firebase/init.js`) ועם `persistentLocalCache` לעבודה offline
- **Capacitor 8** ופלאגינים: `local-notifications`, `push-notifications` / `@capacitor-firebase/messaging`, `@capacitor-firebase/authentication`, `haptics`, `status-bar`, `splash-screen`, `app` (כפתור חזור ו־deep links), `keyboard`, `share`, ובהמשך `@capacitor-firebase/crashlytics`
- הפונט נארז **מקומית** (`@fontsource-variable/rubik`) ולא מ־Google Fonts, כדי שיעבוד גם offline בתוך ה־APK
- **Vitest** לבדיקות לוגיקה, **Playwright** לצילומי מסך השוואתיים

### שכבת Platform
כל יכולת שמתנהגת אחרת בטלפון ובדפדפן עוברת דרך `lib/platform`. דוגמה: `notifications.scheduleReminders(payments, settings)` מתזמן התראות מקומיות באנדרואיד, ובווב לא עושה כלום (שם השרת שולח push). שאר הקוד לא צריך לדעת על איזו פלטפורמה הוא רץ.

## 4. התראות: הסיבה שבגללה עוברים לאנדרואיד

### 4.1 קודם כול, תיקון מודל הנתונים של תשלום חוזר
- נוסיף את `lib/recurrence.js` עם `nextOccurrence(payment, today)` ו־`occurrencesInRange(payment, from, to)`.
- `nextDate` הקיים יהפוך ל"עוגן". אם התאריך כבר עבר, מקדמים אותו לפי `cycle` (יומי, שבועי, חודשי, שנתי) עד שמגיעים לתאריך עתידי.
- יום בחודש נשמר כ־`anchorDay`, כדי ש־31 לא "יזחל" ל־28 אחרי פברואר. בחודש קצר מצמידים ליום האחרון.
- "שולם החודש" יחושב לפי המופע האחרון שכבר עבר, ולא לפי "התאריך עבר".
- **אין צורך במיגרציה של נתונים**, כי החישוב תואם לאחור. אותו מודול משמש גם בפונקציית הענן: סקריפט build מעתיק אותו ל־`functions/`.
- לוח השנה יציג את **כל** המופעים בחודש. מנוי שבועי יופיע 4–5 פעמים.

### 4.2 התראות מקומיות על המכשיר (הבסיס)
כל תאריכי התשלום ידועים מראש, ולכן האפליקציה יכולה לתזמן את התזכורות **בעצמה**, בלי שרת ובלי אינטרנט:
- בכל שינוי בתשלומים או בהגדרות, בכל פתיחה של האפליקציה ובכל חזרה מרקע: מבטלים את התזמון הקיים ומתזמנים מחדש את 60 הימים הקרובים (שבוע, 3 ימים, יום, או ביום עצמו, לפי ההגדרה, בשעה שנבחרה).
- שימוש בהתראות **לא מדויקות** (`allowWhileIdle`). תזכורת ב־09:00 עם סטייה של כמה דקות זה מספיק, וכך לא צריך את הרשאת Exact Alarm (שבאנדרואיד 14 ומעלה חסומה כברירת מחדל).
- הרשאת `POST_NOTIFICATIONS` (נדרשת מאנדרואיד 13): מבקשים אותה **בהקשר**, במסך onboarding שמסביר למה, ולא בפתיחה הראשונה.
- **ערוצי התראות (Channels):** "תזכורות תשלום" (חשיבות גבוהה), "סיכום חודשי", "פעילות משותפת", "צ'ק־אין יומי". המשתמש יכול לשלוט בכל ערוץ בנפרד מהגדרות אנדרואיד.
- **כפתורי פעולה בהתראה:** "✓ שולם" ו־"הזכר לי מחר". לחיצה על ההתראה פותחת את התשלום עצמו (deep link).
- התזמון שורד אתחול של הטלפון (הפלאגין מטפל ב־BOOT_COMPLETED), ובנוסף מתזמנים מחדש בכל פתיחה כרשת ביטחון.

### 4.3 Push מהשרת (FCM נייטיב), לאירועים שהמכשיר לא יודע עליהם
- **מכשירים מרובים:** אוסף חדש `users/{uid}/devices/{deviceId}` עם `{ token, platform, localReminders, updatedAt }` במקום שדה בודד, וחוק Firestore מתאים.
- **פונקציות ענן חדשות או מעודכנות:**
  - `paymentReminders`: שולחת **רק** למכשירי ווב (`localReminders: false`), כדי שלא יגיעו כפילויות לאנדרואיד. מעבר ל־payload עם `android.notification.channelId`.
  - `onSharedExpenseCreated` (טריגר `lists/{id}/items/{id}`): "דנה הוסיפה ₪120 · קניות" לשאר החברים במעקב.
  - `onInviteCreated`: כשמזמינים אימייל, מחפשים את המשתמש (`getUserByEmail`) ושולחים לו push.
  - `monthlySummary` (ב־1 לחודש): "בספטמבר הוצאת ₪4,210, 12% פחות מאוגוסט 🎉". סוף סוף מממש את המתג הקיים.
  - `budgetAlert`: מעבר של 80% ושל 100% מהתקרה. כאן צריך שרת, כי גם שותף יכול להוסיף הוצאה.
- ניקוי טוקנים פגים, כמו שכבר קורה היום.

## 5. שפת העיצוב החדשה

### 5.1 מה לקחתי מהרפרנס
- **אוויר.** רקע לבן־אפרפר, כרטיסים לבנים עם צל שכמעט לא רואים, פינות מעוגלות מאוד (~28px).
- **המספר הוא הגיבור.** הסכום מופיע בגדול (~64px, משקל 900) עם ₪ קטן יותר, ומתחתיו תווית קטנה.
- **פונט עגול וכבד** לכותרות ולמספרים, עם היררכיה חדה: כותרת מסך ענקית מימין, מספר גיבור, ואז פירוט.
- **צבע במינון:** בסיס של שחור, לבן ואפור, ירוק מותג להצלחה ולפעולה, ופסטלים (לבנדר, מנטה, אפרסק, תכלת) לרקעים של כרטיסים מיוחדים ולעיגולים מאחורי אייקונים.
- **אייקונים בסגנון מדבקה:** איורים שטוחים צבעוניים עם קו מתאר שחור עבה. בניווט, אייקון לא פעיל אפור ואייקון פעיל צבעוני, עם נקודה מתחת לתווית.
- **כפתור + מרכזי** ירוק עם מסגרת שחורה עבה. נגיעה נאו־ברוטליסטית שנותנת אופי.
- **גלולות (pills)** לתובנות ולתגים: "חודש ראשון לדיווח 🎉", "1d ⚡", "החודש: 7₪".
- **גרפים רכים:** עמודות בצורת גלולה על מסלול אפור בהיר, עמודה פעילה בירוק עם תווית ערך צפה מעליה, ודונאט עבה עם הסכום במרכז.
- **שורת מדדים עם מפרידים אנכיים:** ממוצע ליום | פעילות | הוצאה שיא.
- **גיימיפיקציה עדינה:** רצף ימים 🔥, יעד תקציב 🎯, אבני דרך.

**מה נעשה טוב יותר מהרפרנס:** ניגודיות טקסט של לפחות 4.5:1 (חלק מהאפורים ברפרנס חיוורים מדי), ודונאט שצבוע לפי קטגוריה ולא טבעת אפורה אחת.

| H1 (כותרת מסך) | 32 / 800 |
| H2 (כותרת סקשן) | 22 / 800 |
| Title | 17 / 700 |
| Body | 15 / 500 |
| Caption | 12.5 / 600 |

כל המספרים עם `tabular-nums`.

**צורה:** רדיוסים 12 / 18 / 24 / 32 / גלולה. צל כרטיס `0 1px 2px rgba(0,0,0,.04), 0 8px 24px rgba(0,0,0,.05)`. קו מתאר "מדבקה" 2.5px ב־`--ink`. ריווח בכפולות של 4.

**מצב כהה:** נשמר (קיים היום), אבל מתוכנן כ"מעבר שני" אחרי שהבהיר מלוטש: רקע `#0E0E10`, כרטיסים `#18181B`, פסטלים בגרסה עמוקה, וקווי המתאר של האייקונים הופכים לבהירים.

### 5.3 אייקונים
אצייר סט SVG אחיד של כ־30 אייקונים בסגנון הרפרנס (מילוי שטוח צבעוני וקו מתאר שחור 2px), כרכיבי React עם שני מצבים: `active` צבעוני ו־`muted` אפור, למעבר מונפש בניווט.
- **ניווט:** בית, ניתוח, מנויים, פרופיל
- **מדדים:** מטבעות, גרף, אש, מטרה, לוח שנה, ברק
- **קטגוריות:** עגלה, ביטוח/מגן, אוכל, בית, רכב, בריאות, בילוי, מתנה, חינוך, חיות, קופסה (שונות)
- **פעולות:** שיתוף, אנשים, פעמון, מנעול

קטגוריות שהמשתמש יוצר יקבלו בחירת אייקון וצבע. זה יישמר ב־`groupMeta` במסמך המעקב, תואם לאחור.

### 5.4 תנועה (Motion)
**טוקנים:** spring ברירת מחדל `{stiffness: 400, damping: 30}`, spring רך `{220, 26}`, משכים 150/250/400ms, easing `cubic-bezier(.22,1,.36,1)`.

**אנימציות החתימה:**
1. **מספרים מתגלגלים.** כל סכום גיבור מתגלגל ספרה אחר ספרה במעבר חודש או בהוספת הוצאה.
2. **עמודות צומחות** מלמטה בדירוג של 40ms בין עמודה לעמודה. תווית הערך "קופצת" מעל העמודה הפעילה.
3. **דונאט נמתח** בכיוון השעון מקטע לקטע, והסכום במרכז נספר.
4. **סרגל ניווט:** האייקון הפעיל עובר מאפור לצבעוני עם קפיצה קטנה (0.9 → 1.08 → 1), והנקודה מחליקה בין הטאבים (`layoutId`).
5. **כפתור +:** בלחיצה מתכווץ (0.9), הגיליון עולה ב־spring, וה־+ מסתובב 45° והופך ל־×.
6. **גיליונות (sheets):** פיזיקת spring אמיתית וגרירה לסגירה לפי מהירות. הרקע מתעמעם בהתאם לגרירה. מחליף את קוד המגע הידני הקיים.
7. **רשימות:** פריטים נכנסים עם fade ועלייה של 8px, בדירוג של 30ms. מחיקה מכווצת את הגובה ומחליקה החוצה.
8. **לחיצה על כרטיס:** כיווץ ל־0.97 ב־spring, יחד עם haptic קל.
9. **מעבר חודש:** החלקה אופקית שמודעת ל־RTL, וגם מחווה של swipe על הכרטיס.
10. **הצלחה:** וי שמצטייר (SVG path) עם haptic הצלחה. באבני דרך: קונפטי.
11. **להבת הרצף** מהבהבת בעדינות כשהרצף פעיל.
12. **טעינה:** skeleton עם shimmer במקום ספינרים.

**כללי ביצועים:** מנפישים רק `transform` ו־`opacity`. אין `backdrop-filter`, אין אנימציה של `box-shadow` או `height` (גובה עובר דרך layout animation או grid-rows). רשימה ארוכה (מעל 200 פריטים) עוברת וירטואליזציה. הכול מכבד `prefers-reduced-motion`.

**Haptics:** טיק בחירה בלחיצה על מקלדת, segment או חודש. קל בלחיצה על כרטיס או טאב. בינוני על כפתור +. הצלחה בשמירה. אזהרה במחיקה ובחריגה מתקציב.

### 5.5 רכיבי ה־Design System (`src/ui`)
`Screen` · `ScreenTitle` · `Card` · `PastelCard` · `StatTile` (אייקון בעיגול פסטל + מספר + תווית, כמו ברפרנס) · `StatRow` (עם מפרידים) · `Pill` · `HeroAmount` · `AnimatedNumber` · `MonthSwitcher` · `BarChart` · `Donut` · `ProgressBar` · `CategoryRow` · `ListRow` · `Avatar`/`AvatarStack` · `Button` (ראשי ירוק עם מסגרת, משני, רפאים) · `IconButton` · `SegmentedControl` · `Chip` · `Toggle` · `Sheet` · `Keypad` · `EmptyState` (עם איור) · `Skeleton` · `Toast` · `ConfirmDialog` · `TabBar` + `Fab`

הגרפים ייכתבו ב־SVG ידני עם motion, בלי ספריית גרפים. הם פשוטים מדי בשביל להצדיק 100KB של Recharts.

## 6. מבנה המסכים החדש

### סרגל ניווט: `בית | ניתוח | ( + ) | מנויים | פרופיל`
זה ממפה את מה שיש היום (הוצאות, מנויים, לוח, הגדרות) ומוסיף מסך ניתוח כמו ברפרנס. לוח השנה עובר להיות תצוגה בתוך "מנויים", כי הוא ממילא מציג רק מנויים. (החלטה פתוחה, סעיף 10.)

### מסך פתיחה + Onboarding (חדש)
3 שקפים עם איורים ("כל ההוצאות במקום אחד", "תזכורות לפני כל חיוב", "תקציב שמתעדכן לבד"), כניסה עם Google נייטיב, שלב הרשאת התראות עם הסבר, ושלב אופציונלי של הגדרת הכנסה ותקרה עם מקלדת מספרים גדולה.

### בית
- **כותרת:** אווטאר, "שלום, [שם]", ומתחת גלולות של `📅 החודש: ₪X` ו־`🔥 Nd`.
- **מספר גיבור:** "נשאר לבזבז ₪1,240", ומתחתיו פס התקדמות לתקרה. בלי תקרה מוגדרת: "הוצאת החודש", וכפתור "הגדר תקציב".
- **רשת 2×2 של StatTiles:** סך החודש · עסקאות החודש · רצף ימים · % מהיעד.
- **"החיובים הקרובים":** קרוסלה אופקית של 3–5 המנויים הבאים, עם בועת המותג וספירה לאחור ("בעוד 3 ימים").
- **כרטיס פסטל לבנדר "מעקב משותף":** ערימת אווטארים של השותפים ופעילות אחרונה.
- **"הוצאות אחרונות":** 5 אחרונות וקישור "להיסטוריה המלאה", שהוא מסך נדחף עם חיפוש, פילטר לפי קטגוריה וקיבוץ לפי יום או קטגוריה (התצוגות שקיימות היום).

### ניתוח (בדיוק לפי צילום המסך הראשון)
כותרת "ניתוח הוצאות" · מחליף חודשים · **סכום ענק** עם גלולת תובנה ("‎-12% מספטמבר" / "חודש ראשון לדיווח 🎉") · **השוואה חצי שנתית** (6 עמודות גלולה, הנוכחית בירוק עם תווית) · **StatRow:** ממוצע ליום | פעילות | הוצאה שיא · **קטגוריות מובילות** (אייקון, שם, %, סכום ופס, ולחיצה פותחת את הקטגוריה) · **התפלגות הוצאות** (דונאט צבעוני עם סה״כ במרכז) · **הוצאות יומיות** (העמודות הקיימות, מעוצבות מחדש) · **קצב מול תקציב** (מה שהיום נמצא ב־BudgetDetailSheet).

### + (הוספה מהירה)
גיליון עם segmented למעלה: `הוצאה | מנוי קבוע`.
- **הוצאה:** סכום ענק שמתגלגל בזמן הקלדה, מקלדת מספרים מותאמת (בלי מקלדת המערכת ובלי קפיצות), רשת קטגוריות עם אייקונים בעיגולי פסטל, שם עם הצעות מהוצאות אחרונות, צ'יפ תאריך (היום / אתמול / 📅), וכפתור "שמור" ירוק מלא עם מסגרת. **היעד: הוספת הוצאה בפחות מ־5 שניות.**
- **מנוי קבוע:** הזרימה הקיימת של `AddSheet` (קטלוג השירותים, חיפוש, שירות מותאם), מעוצבת מחדש.

### מנויים
- **גיבור:** "₪612 לחודש · 9 מנויים", ומתחת "שנתי: ₪7,344".
- **כרטיס "החיוב הבא":** בועת מותג גדולה וספירה לאחור.
- **Segmented:** `רשימה | לוח שנה`.
  - **רשימה:** ציר זמן מקובץ ("השבוע", "החודש", "בהמשך"), ושורות עם בועת מותג, שם, מחזור וסכום.
  - **לוח שנה:** הלוח הקיים בעיצוב חדש, עם נקודות צבעוניות ועם **כל** המופעים (תודות לתיקון בסעיף 4.1).
- **פירוט לפי קטגוריה ומחזור** (מה שהיום נמצא ב־StatsDetailSheet).

### פרופיל (בדיוק לפי צילום המסך השני)
כרטיס כותרת (אווטאר, שם, גלולות) · **רשת 2×2:** סך הכל השנה · עסקאות החודש · רצף ימים פעיל · יעד תקציב חודשי (עם פס) · **כרטיסי פסטל:** "שיתוף הוצאות" (לבנדר) ו"מעקב נוסף" (מנטה) · **סקירת 12 חודשים** (עמודות גלולה) · **הישגים** (תגים) · **הגדרות** מקובצות: תקציב, התראות (עם קישור לערוצי אנדרואיד), מראה, מטבע, ייצוא, חשבון.

### גיליונות (sheets)
פרטי הוצאה · פרטי מנוי · עריכת קטגוריות (עם בחירת אייקון וצבע) · שיתוף והזמנה (עם Share Sheet נייטיב לקוד ההזמנה) · הגדרות תקציב. כולם על רכיב ה־`Sheet` החדש.

### כפתור "חזור" של אנדרואיד
סוגר את הגיליון העליון. אם אין גיליון פתוח, חוזר למסך הקודם או לטאב "בית". בטאב "בית" יוצא מהאפליקציה.

## 7. שלבי ביצוע

> גודל יחסי: **S** קטן, **M** בינוני, **L** גדול. כל שלב נכנס ב־PR משלו לענף הפיתוח. **אתר הווב החי לא נפגע**: `deploy.yml` מפרסם רק מהענף `claude/implement-payments-page-G9fij`, וממזגים אליו רק שלב שאחריו הווב עדיין עובד.

### שלב 0: פרוטוטייפ עיצובי לאישור (S)
עמוד HTML אינטראקטיבי עם 3 מסכים (בית, ניתוח, הוספה מהירה) בשפה החדשה, עם אנימציות אמיתיות ושני פונטים לבחירה, שאפשר לפתוח בטלפון.
**קריטריון:** אישור שלך לכיוון, לפונט ולצבעים, **לפני** שכותבים מחדש 5,700 שורות.

### שלב 1: תשתית (M)
- מעבר ל־Vite ו־ES modules: כל `Object.assign(window, …)` הופך ל־import/export, React בגרסת production, בלי Babel בדפדפן
- Firebase מודולרי עם config מפורש
- Tailwind + `tokens.css` + מצב demo עם נתוני דמו
- `lib/recurrence.js` עם **תיקון באג התזכורות** ובדיקות Vitest לחישובי תאריכים ותקציב
- עדכון `deploy.yml` (`npm ci && npm run build`, ו־Hosting מגיש את `dist/`) ועדכון ה־Service Worker
- **קריטריון:** האפליקציה בווב נראית ומתנהגת **בדיוק** כמו היום, נפתחת מהר יותר, והבדיקות ירוקות.

### שלב 2: מעטפת אנדרואיד (M)
- `npx cap add android`, package name (הצעה: `com.ohavs.payments`), אייקון אדפטיבי, splash
- כניסה עם Google נייטיב (`@capacitor-firebase/authentication` ואז `signInWithCredential`); אנונימי נשאר כמו שהוא
- edge-to-edge, safe areas, status bar, מקלדת, כפתור חזור, חסימת overscroll
- `targetSdk 36` (הדרישה העדכנית של Google Play)
- **CI:** כל PR בונה APK debug שאפשר להוריד כ־artifact
- **קריטריון:** מתקינים APK בטלפון, נכנסים עם Google, ורואים את הנתונים הקיימים.

### שלב 3: התראות (M–L)
- התראות מקומיות: תזמון, ערוצים, כפתורי פעולה, deep links, מסך בקשת הרשאה
- אוסף `devices`, FCM נייטיב, וחוקי Firestore מעודכנים
- Cloud Functions: הפרדה בין ווב לאנדרואיד, פעילות משותפת, הזמנות, סיכום חודשי, התראות תקציב
- מסך "התראות" בפרופיל עם כפתור "שלח התראת בדיקה"
- **קריטריון:** תזכורת מגיעה כשהאפליקציה סגורה ובמצב טיסה (מקומית). הוספת הוצאה ע"י שותף מקפיצה push. אין כפילויות.

### שלב 4: Design System + ניווט + בית + הוספה (L)
- טוקנים סופיים, פונט, סט אייקונים, כל רכיבי `src/ui`
- `TabBar` ו־`Fab` עם האנימציות, מעברי מסכים, `Sheet` חדש על motion
- מסך **בית** ו**הוספה מהירה** (כולל המקלדת)
- הסרת glassmorphism ו־orbs
- **קריטריון:** צילומי מסך של בית והוספה תואמים לפרוטוטייפ, ובטלפון זה רץ ב־60fps.

### שלב 5: ניתוח + מנויים + פרופיל + Onboarding (L)
- כל המסכים מסעיף 6, כולל ההיסטוריה המלאה והלוח החדש
- העברת כל הגיליונות הקיימים לעיצוב החדש
- ייצוא CSV אמיתי (נשמר דרך Share Sheet)
- **קריטריון:** אין יותר אף מסך בעיצוב הישן.

### שלב 6: "וואו": ליטוש, גיימיפיקציה, מצב כהה (M)
- רצף ימים, צ'ק־אין יומי, תגי הישגים, קונפטי באבני דרך
- גלולות תובנה חכמות ("ההוצאה הכי נמוכה מתחילת השנה", "חסכת ₪300 לעומת הממוצע")
- empty states מאוירים, skeletons, מעבר על כל ה־haptics
- מצב כהה מלא
- מעבר ביצועים על מכשיר בינוני
- **קריטריון:** "מטורף" 🙂 (הבדיקה היא שלך).

### שלב 7: הפצה (S–M)
- keystore לחתימה כסוד ב־GitHub, וורקפלואו `release-android.yml` שבונה AAB ו־APK חתומים על כל tag `v*`
- הפצה לפי ההחלטה בסעיף 10: GitHub Releases / Firebase App Distribution / Google Play
- Crashlytics ודף מדיניות פרטיות (Play דורש)

### אחר כך (לא בהיקף הנוכחי)
- **ווידג'ט למסך הבית** ("נשאר לבזבז", "החיוב הבא"). דורש קוד Kotlin/Glance, והנתונים יעברו דרך SharedPreferences.
- הוספת הוצאה ישירות מהתראה (inline reply)
- נעילה ביומטרית
- ייצוא PDF
- iOS, שהוא כמעט "בחינם" עם Capacitor
